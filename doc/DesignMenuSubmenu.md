## 1. 核心决策与范围

采用以下结构：

- 模型递归嵌套，父 `PopoverMenu` 递归拥有子 `PopoverMenu`。
- Window 只登记根菜单作为唯一 `ModalTarget`。
- 主窗口保留原生键盘焦点，向根菜单转交按键；菜单自己确定键盘活动层。
- 显示中的子菜单不必始终占有键盘，显示分支与键盘活动分支分别记录。
- 原生 Popup 的绘制、尺寸和常规鼠标事件仍由对应 Popover 处理。
- 继续使用原生 Popup，不新增平台公共接口，不修改 Painter。

不引入独立 `menuSession`、全局菜单管理器、模态栈或另一份展开链数组。

计划完成多级展开、鼠标切换和跨菜单移动、基本键盘导航、工作区退避、
长菜单滚动、动态模型和虚拟行生命周期、UI 递归声明及统一外观。

本次不做 Overlay、菜单栏、助记键、输入搜索、快捷键列、富控件菜单、
可聚焦原生 Popup 或完整输入法宿主能力。

### 1.1 职责边界

| 层／对象 | 职责 |
|---|---|
| platform Popup | 原生表面、绘制通知、输入事实、坐标转换 |
| gui.Window | 主窗口输入入口、唯一根模态目标 |
| Popover | 表面生命周期、布局、定位、局部事件分发 |
| PopoverMenu | 菜单交互、父子关系、键盘活动层、展开与关闭 |
| menuContent／menuItemRow | 内容测量、滚动、绘制、事件控制器及交互反馈 |
| Menu／MenuItem | 纯数据与变更通知 |
| ui | 声明协调，不另建菜单交互机制 |
| style／theme | 外观，不决定展开、关闭或键盘活动层 |

### 1.2 替代旧备忘的内容

旧备忘中的以下方案不再实施：

- 不让每一级子菜单独立登记 Window 的 ModalTarget。
- 不把展开协调和子 Popup 所有权放进虚拟列表行或 menuContent。
- 不增加 `Popup.AbsPosition()`、屏幕坐标 API 或公共 OwnerWindow getter。
- 不再由 Window 提前把 Esc 转换成整链关闭请求。
- 不在 Action 执行之后才关闭菜单。
- 不把“最深可见菜单”无条件等同于键盘目标。

## 2. 公共模型 API

沿用现有 `MenuModel`，不再增加新的模型接口：

```go
func (mi *MenuItem) Submenu() MenuModel
func (mi *MenuItem) SetSubmenu(model MenuModel)

func (m *Menu) AppendSubmenu(
    label string,
    submenu MenuModel,
) *MenuItem
```

使用示例：

```go
recent := gui.NewMenu()
recent.Append("project-a", openProjectA)
recent.Append("project-b", openProjectB)

menu := gui.NewMenu()
menu.Append("打开", openFile)
menu.AppendSubmenu("最近打开", recent)
menu.AppendSeparator()
menu.Append("退出", quit)

popup := gui.NewPopoverMenu(anchor)
popup.SetMenu(menu)
```

### 2.1 条目语义

| 条目情况 | 行为 |
|---|---|
| 子模型为 nil | 普通项，激活时执行 Action |
| 子模型非 nil | 展开项，确认只展开，不执行自身 Action |
| 禁用或隐藏 | 不可激活、不可展开 |
| 分隔线 | 始终不参与交互 |
| 子模型没有可见的非分隔项 | 不弹出空菜单，不退回执行父项 Action |
| 子模型只有禁用项 | 可以展开并显示禁用项 |

`SetSubmenu(nil)` 恢复普通项语义。子模型改变通过现有模型通知刷新显示。

展开状态、当前项、Timer、Widget 和原生资源不写入模型。同一个模型可供多个
宿主使用，每个宿主的交互状态相互独立。GUI 状态及模型的 GUI 使用仍遵守事件线程
约定，不因底层列表容器有锁就宣称整套菜单支持并发操作。

模型结构不得形成循环。展开时检查当前祖先路径，拒绝循环分支并输出诊断；
不扫描整棵模型预建菜单，也不设置任意的固定层数上限。UI 递归构建同样必须
防止循环声明造成无限递归；不同分支复用同一份合法数据不等于循环。

### 2.2 Action 更新

增加：

```go
func (mi *MenuItem) SetAction(action func())
```

只更新行为，不触发布局或菜单重建通知。UI 用它刷新闭包，不比较函数地址。

## 3. 父子归属与生命周期 API

```text
gui.Window
└─ ModalTarget → PopoverMenu A
                   ├─ Popover A → menuContent A
                   └─ child → PopoverMenu B
                                 ├─ Popover B → menuContent B
                                 └─ child → PopoverMenu C
```

每一级最多展开一个子菜单，主要私有状态示意：

```go
type PopoverMenu struct {
    // 现有模型、内容、Popover、信号等字段……

    parent *PopoverMenu // 非拥有引用
    child  *PopoverMenu // 本级拥有

    childItem       *MenuItem
    keyboardInChild bool

    // 当前项、延迟任务、生命周期代次等私有状态。
}
```

- 父菜单创建、关闭并销毁子菜单。
- parent 仅用于返回上级、找到根菜单，不反向拥有父资源。
- 行报告交互，不持有子菜单生命周期。
- 展开来源使用模型条目、索引和绑定代次校验，不以行指针作为唯一身份。
- 所有原生 Popup 仍以同一个主窗口作为平台 owner。
- 原生 owner 与 GUI 对象的拥有关系是两个概念。

增加：

```go
func (pm *PopoverMenu) Destroy()
```

`Hide()` 结束显示，允许再次打开；`Destroy()` 永久释放资源和连接，之后不能重新
显示。二者幂等，销毁后的 Show 返回错误。

根菜单隐藏后可保留原有表面以便下次复用；内部子菜单关闭后销毁，不为每个曾经展开
过的条目永久缓存 Popup。锚点卸载、窗口销毁继续作为资源清理兜底。

## 4. 原生焦点与模态登记

保留当前 Popup 不主动抢主窗口焦点的配置，不为了统一事件来源而改为每级 Popup
依次获得原生键盘焦点。

| 事件 | 接收与处理 |
|---|---|
| 绘制、尺寸 | 对应 Popup → 对应 Popover |
| 鼠标、滚轮 | 对应原生表面 → 菜单局部输入路径 |
| 按键 | 主窗口 → 根菜单 → 当前键盘活动层 |

原生消息的接收者不等于逻辑交互的解释者。以后若 Popover 需要完整文本编辑和输入法，
单独设计可聚焦 Popup／文本输入宿主，不把本次 KeyEvent 转发当作完整输入法支持。

根 `PopoverMenu` 实现现有协议：

```go
func (pm *PopoverMenu) DispatchEvent(event events.Event) error
func (pm *PopoverMenu) RequestDismiss()
```

- 根菜单显示成功后登记为 Window 的 ModalTarget。
- 子菜单不调用 `Window.SetModalTarget`。
- `RequestDismiss` 表示关闭整条菜单链。
- 菜单使用的底层 Popover 不再分别登记模态目标。
- 普通 Popover 独立使用时保持现有模态能力。

解除登记必须匹配本次登记的身份／代次。旧菜单关闭回调或旧清理不能清掉新菜单的
登记。保护属于 Window 内部登记机制，不需要模态栈；Window 不因此认识菜单结构。

## 5. 按键路由与活动层

### 5.1 Window 只转交按键

移除 Window 对 Esc 的提前拦截，所有 KeyEvent 交给模态目标：

```go
case events.KeyEvent:
    _ = target.DispatchEvent(event)
    return true
```

菜单打开期间按键不再进入主窗口 Widget 树。Window 仍对主窗口上的外部点击、
失焦等情况请求根目标关闭。普通模态 Popover 在自己的路径里保留 Esc 关闭逻辑。

### 5.2 显示分支与键盘活动分支分离

例如鼠标回到 A 的其他有效项，而 B 正处于延迟关闭期间：

- `A.child == B`：B 仍显示。
- `A.keyboardInChild == false`：按键由 A 处理。

每一级按以下规则分发：

1. 若存在有效的活动子分支，转交子菜单。
2. 否则交给本级 Popover 的内容事件分发器。
3. 内容上的 KeyEventController 解释菜单行为。

```text
原生主窗口收到按键
    ↓
gui.Window.DispatchEvent
    ↓
根菜单 A
    ↓ 当前键盘活动分支
子菜单 B
    ↓
B 的 Popover → EventDispatcher → KeyEventController
```

进入某一层时，更新通往该层的祖先活动路径。关闭子菜单后父级收回键盘处理权。
一个事件只交给一个最终目标，不广播；已经处理的 Esc 不再沿父链重复消费。

### 5.3 活动层变化

- 点击或键盘展开子菜单：成功后进入子级。
- 悬停展开子菜单：成功后进入子级，但不强制选择第一项。
- 鼠标真实移动并选择祖先菜单项目：活动层回到该祖先。
- 单纯经过阴影、空白或重布局产生的 Crossing，不抢走键盘活动层。
- 延迟打开尚未完成时，活动层仍在父级；打开失败也不转移。
- 本层没有有效 child 时，keyboardInChild 必须为 false。

### 5.4 键盘语义

| 按键 | 行为 |
|---|---|
| ↑／↓ | 上一／下一可用项，首尾循环 |
| Home／End | 第一／最后可用项 |
| → | 展开当前项，进入子级并选中首个可用项 |
| ← | 关闭当前子菜单及后代，返回父项；根级不处理 |
| Enter／Space | 展开当前项或激活叶子项 |
| Esc | 关闭当前活动层及后代；根级关闭整条链 |
| Tab／Shift+Tab | 关闭整条链，消费本次事件 |

隐藏、禁用、分隔线和空子菜单不作为键盘候选项。无当前项时，向下选择第一项，
向上选择最后一项；没有任何可用项时导航无操作，返回／关闭仍有效。

导航后将当前项滚入可见视口，不把焦点指向尚未创建或已回收的行。
左右键表达进入／返回，不随菜单实际左右退避而翻转。

确认、展开、退出类按键不因自动重复连续触发多个层级；上下导航可以重复。
鼠标实际选择和键盘选择共享明确的当前项状态，不由普通重绘改变选择。

## 6. 鼠标展开与分支切换

初始内部常量：

- 悬停展开／切换延迟：250ms。
- 朝子菜单移动的保护上限：500ms。

这些是 GUI 交互参数，不是平台事实或样式字段；真机体验后可以调整。

行为约定：

- 悬停可展开项，延迟打开。
- 左键点击立即打开。
- 点击已展开的父项，保持展开，不进行开关切换。
- 进入兄弟项，延迟关闭旧分支；新项可展开时再打开。
- 离开父行不立即关闭子菜单。
- 进入子菜单后，取消祖先中尚未执行的分支切换任务。
- 空白、分隔线、禁用行不启动新分支；选择其他有效项目时才切换当前项。
- 父项有独立的展开高亮，不依赖鼠标仍留在父行。

### 6.1 斜向移动保护

根据子菜单最终主体矩形及最近指针轨迹，判断是否正朝子菜单移动，满足时暂缓兄弟
切换。左右退避后使用对应方向；点击立即生效，不受保护阻挡；保护期限不能随移动
无限延长。无法形成合理通道时，回到普通延迟策略。

算法独立于父子归属。先完成可靠的延迟与跨菜单进入处理，再加入方向保护；
不为本功能修改公共手势竞争机制。

### 6.2 延迟任务与线程

使用 Timer 向应用事件线程投递任务，后台回调不访问菜单或 Widget 状态。

执行前检查：

- 菜单仍显示、未销毁。
- 生命周期／任务代次匹配。
- 候选条目、索引及绑定仍有效。
- 条目仍允许展开。
- 触发行仍处于有效视口。

取消任务既停止 Timer，也使已入队的旧任务失效。测试通过可控调度推进时间，
不靠真实 sleep 碰时序。

## 7. 跨 Popup 指针路由

常规鼠标事件仍由对应 Popover 处理，不把所有指针事件先绕到 Window。

需要协调的情况是子菜单表面覆盖祖先，例如透明阴影盖住父菜单行。不能仅根据事件
来自哪个 Popup 就确定菜单命中。

流程：

1. 将指针／滚轮位置转换为主窗口客户区 DIP。
2. 存在有效指针捕获时，移动和抬起优先交给捕获宿主。
3. 否则从最深一级向上检查实际圆角主体。
4. 转换到命中菜单的局部坐标。
5. 进入目标 Popover 的内容事件分发器。

B 阴影下面是 A 的行时交给 A；命中 B 主体时交给 B；没有命中任何主体的按下关闭
整条链。主窗口上的外部按下沿用关闭并消费的策略，不透传给底层控件。

输入宿主改变时清理旧 Hover／Pressed，避免跨原生表面残留状态。
路由只选择接收者，项目点击、滚动和按键语义仍经过 EventDispatcher 和
EventController，不直接调用 Action。

不添加全局鼠标监听来模拟其他应用的输入；应用外关闭继续依赖已有原生失焦等事实。

## 8. Popover 内部协作

公共 Popover 接口不扩张。内部增加少量基于信号的协作点：

- 输入接管：菜单宿主可协调跨表面路由。
- 关闭前通知：表面释放前清理后代。
- 布局完成通知：在父级布局完成后更新子菜单锚点。

提供私有的“直接分发到内容”入口，完成路由后进入 EventDispatcher，
避免再次触发输入接管造成递归。

Popover 不保存 *PopoverMenu，不解释菜单按键，不处理兄弟分支切换。
连接由菜单宿主管理，Popover 替换和销毁时断开；普通 Popover 无协作连接时
保持原有行为。通知之后必须重新检查生命周期，不能假设回调不会关闭表面。

## 9. 子菜单定位与尺寸

### 9.1 坐标

继续使用主窗口客户区 DIP，不增加全局屏幕坐标 API。

```text
父 Popup 最终提交的表面位置
    + 触发行在父 Popup 内的局部位置
    = owner 客户区中的触发行位置
```

使用已完成退避的内部表面位置，不用公开 Popover.Position() 的原始请求值；
阴影占位和滚动偏移只计算一次。保留原生尺寸事件作为实际尺寸事实，
GUI 请求值不能冒充原生观测结果。

扩展内部锚点 owner 解析，让 Popover 内的 Widget 能找到真正的主窗口。
不改变公共 Widget.Window() 的现有语义，不增加公共 OwnerWindow getter。

### 9.2 候选位置

- 水平贴父菜单主体侧边，不贴带内边距的行边缘。
- 子菜单主体顶部对齐触发行顶部。
- 第一层优先右侧，更深层优先延续父级实际展开方向。
- 首选侧不能容纳时尝试另一侧。
- 两侧均不能容纳时，选择溢出较少的候选，再平移进工作区；
  溢出相同时保留首选方向，保证求解确定。
- 只有完整表面超过工作区尺寸时才约束内容并启用滚动。

主体之间默认不加装饰性间隙，阴影可重叠。对齐按主体计算，容纳按包含阴影的表面
计算。复用工作区快照、内容决定尺寸、原生尺寸取整校正及既有错误／降级约定，
不新增菜单默认固定宽高。

### 9.3 父级布局变化

父级完成布局后，再从父到子更新位置：

- 触发行完整可见：重新定位。
- 触发行部分或全部滚出有效视口：关闭子分支。
- 行解绑、回收或条目失效：关闭相关分支。
- 样式、字号、内容尺寸变化：重新求解，不使用旧坐标。

是否可见依据有效视口及裁剪，不只看行的 Visible 标志。
子菜单位置更新不反向修改父级自然尺寸，避免布局反馈循环。

## 10. 模型更新与虚拟列表

当前 ListView 可能在模型通知后解绑并重建可见行。采用明确、保守的策略：

- 当前层发生显示／结构变化：取消待展开任务，关闭依赖旧行的后代，重新布局。
- 当前层本身保持打开；当前项仍有效则保留，否则修正或清空。
- 子模型变化由子菜单自己订阅，不要求父模型递归转发后代通知。
- 子菜单内容变空时关闭子菜单，父菜单保留。
- Action 更新不重建显示，不关闭分支。

不为了保留所有展开状态而实现复杂模型差量协调。

临时测量行只测量，不连接展开生命周期，不创建 Popup。真实行在 Unbind 前
通知菜单控制器清理旧绑定对应的状态。恢复键盘当前项依据条目身份和布局结果，
不能继续使用回收前的 Widget 指针。

## 11. 关闭、销毁、回调与失败

### 11.1 关闭范围

- B.Hide()：关闭 B 及后代，A 保留。
- 根菜单 Hide()：关闭整条链。
- 叶子激活：保存 Action，关闭整条链，然后执行 Action。
- 锚点卸载、窗口销毁、原生表面释放：递归清理受影响分支。
- 外部 RequestDismiss：由根菜单结束整次交互。

### 11.2 清理顺序

1. 标记关闭并使延迟任务失效。
2. 断开旧父子关系，防止重入沿旧链操作。
3. 根菜单解除属于自己的模态登记。
4. 从最深层清理输入、隐藏／销毁表面。
5. 对已经完成的可见→隐藏转换发送关闭信号。

ConnectClosed 只报告本菜单关闭，每次可见→隐藏转换最多一次。
子菜单关闭不触发根 MenuButton.ConnectClosed。

关闭信号或 Action 可以重新打开菜单、销毁窗口；旧操作必须检查代次，
不能继续操作新状态，也不能用清空全部信号连接来兜底。
释放连接、Timer 和原生资源必须有明确归属。

### 11.3 打开失败

只有子菜单成功显示，才提交展开状态和键盘活动层。失败清理候选子菜单，
父菜单保持可用。

工作区查询失败与透明创建失败分别处理。透明创建失败沿用当前重试为不透明表面的
规则，不把布局或查询错误当成透明能力失败。

不因鼠标持续停在原位而自动不断重试；重新进入或再次点击可发起新的尝试。

## 12. 样式与语义

各层级复用现有 menu、menu-item、文字及分隔线样式：

- 相同圆角、阴影、边框及中性高亮。
- 展开父项和键盘当前项默认使用高亮，不新增加粗焦点边框。
- 箭头采用矢量绘制，有独立布局列。
- 同层存在子菜单时统一预留指示区域，与文字和滚动条间距分开计算。
- 默认箭头向右，已展开且向左退避时可指示实际方向。
- 文字仍用独立 Label，通过自己的 StyleName 解析样式，父行不向其传递样式。

行快照通过 WidgetInfo.Attributes／SetAttribute 的具名值快照表达 Expandable、Expanded，保留 RoleMenuItem 和 ActionClick；不向 gui.Info 新增菜单专属公共字段。
前者描述子菜单条目性质，后者描述实际展开状态；模型声明了子菜单不等于已展开。

自动化仍通过输入展开菜单，不新增直接执行的语义捷径。不把原生 Popup 内容伪装为
主窗口 Widget 子树，也不借此增加全局 Popup 注册表。当前 Window.Popovers 与 dev 的 ref 已能枚举可见独立宿主；子菜单应复用该能力，不重复创建全局菜单／Popup 注册表。

## 13. UI 层

增加：

```go
func (m *MenuItemView) Submenu(
    items ...*MenuItemView,
) *MenuItemView
```

示例：

```go
ui.MenuButton("文件").Menu(
    ui.MenuItem("打开", openFile),
    ui.MenuItem("最近打开", nil).Submenu(
        ui.MenuItem("project-a", openProjectA),
        ui.MenuItem("project-b", openProjectB),
    ),
    ui.MenuSeparator(),
    ui.MenuItem("退出", quit),
)
```

协调规则：

- 递归构建 gui.Menu。
- 指纹包含子菜单存在性、层级边界、标签、启用状态和分隔线。
- 明确区分普通项与显式声明的空子菜单，包括调用 Submenu() 不传项目的情况。
- 结构不变时保留模型，递归调用 SetAction 刷新闭包。
- 结构变化沿用模型重建策略，关闭失效分支，不做复杂展开状态迁移。
- 不比较函数地址，不保留旧闭包，不让 UI 管理展开状态。
