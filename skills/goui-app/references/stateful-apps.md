# 有状态工作区：数据视图、多文档与多窗口

适用于需要保留编辑、选择、滚动或跨窗口状态的应用。先读 SKILL.md 的源码基线和
依赖规则，再核对同版本公开接口。本参考不要求采用某一种 MVVM、目录或导航结构。

## 先区分要保留的对象

- 业务文档／模型、每个视图的选区与滚动、窗口／Painter 资源分别确定所有者。
  同一文档可以有多个视图，但不应通过反复复制全文在两份独立历史间同步。
  持久文本使用相应 TextModel／文档接口；全文替换是业务操作，不是普通刷新手段。
- UI 重建不等于重新打开文档。ListView、TreeView、TableView 重用非 nil 模型指针，
  用模型通知或 Refresh 更新内容，避免 SetModel 重装导致用户状态重置。
  数据项、列、标签和窗口 ID 各自稳定；行索引和临时 Widget 指针不是业务身份。
- 明确哪些属性由应用持续控制。Selection／Current／Sort 等声明可能在重建时重新
  应用；需要保留用户状态时遵循对应接口的省略语义。TableColumn.Width 是受控声明，
  省略时保留手动宽度；需要持久化时接 OnResize 并回写应用状态，不重复写入初始值。
- 自动列分配的实际宽度和基础 Width 不同。Expand 分配多余空间，MinWidth 限定
  不足时的收缩；自动分配不表示一次用户 Resize，不从瞬时分配反写用户基础宽度。
- 挂载对象保留不代表几何立即稳定。跨视图／窗口恢复选区、折叠或视口时，使用
  对应公开状态接口，核对文档修订、目标身份和就绪条件；不要反复覆盖用户新操作。

## 持久关联与挂载后的操作

- Target 是绑定，Group 是成员之间行为／外观联动，Scope 是命名及管理范围。
  不为单纯关联增加分组容器，也不把不同类型的组并成一个全局字符串注册表。
- ui.ScrollBar(axis, targetID) 和 wui.TabBar(targetID) 已提供持久 Target。
  关联在当前 UI Root 中解析 Widget ID，目标的局部替换也会重绑，不需要双方一起重建。
  自定义 WidgetView／ComposeView 在 Update／Build 中用 ui.BindTarget 声明关联，
  用稳定的 property 名区分用途；回调收到零值时释放自己建立的连接和借用引用。
- App.FindWidget 返回当前借用对象；一次 AfterUpdate 查找只覆盖那次更新，不能
  跟随另一局部后来独立替换的目标。AfterUpdate 适合当次内容完成协调后的聚焦等操作，
  但不代表布局完成、窗口激活或已经呈现；不以固定延时替代各自的就绪条件。
- 普通回调可能关闭窗口、删除目标或重新打开界面。处理后继续访问借用对象前检查
  生命周期与业务代次；异步结果还要校验请求身份，不把旧结果写给新挂载的同名控件。

## 虚拟化、拖放与跨窗口移交

- 虚拟行会绑定、解绑和复用。行 Widget 只持有本次绑定状态；清理拖放、当前行等
  临时反馈，不保留旧行索引或业务对象。普通 ListRowGroup 的连接行外观不提供虚拟化。
- TreeView 的 RowStyle、RowInsets、RowContentDepth 和连续选区信息可组合行外观与
  缩进提示。普通 ListView 的自然宽度及行分配契约不同，不能直接套用树的视口行行为；
  GUI 有委托也不表示声明式接口可替换内部委托。先查同版本接口，不遍历所有行强制实现。
- 虚拟化拖放把 DragSource 装在稳定的树／列表上，在 OnPrepare 中按位置解析业务项，
  捕获有效的数据快照。行回收不取消会话；移除拖拽源或卸载其所属树会取消会话。
  Local 拖放值仍由应用管理，不能认为框架已深拷贝引用指向的数据；跨应用用公开格式。
- 清理所有拖放终态，保留框架的手势竞争和自动滚动。预览属于可选反馈，创建失败
  不应变成永久禁用后续预览的应用状态；真正的拖放错误仍按结果处理。
- 标签跨窗使用 wui 的协调转移、OnTransfer／OnDetachRequest 入口，保证相关 ID 和目标
  声明齐全。转移成功后更新两侧声明集合并请求普通更新，不同步嵌套协调、不重新
  创建页面内容或直接修改受管 Parent。关闭最后一个源窗口后继续验证再次拖动。

## 滚动、测量和视觉边界

- 给虚拟内容明确的可用视口或合理的最小尺寸，不依赖首次测量已知所有行高，也不
  通过实现全部行取得自然高度。普通内容需要按宽度换行时用 ScrollVertical；
  Scrollable 内容仍负责其可见布局，必须保留无界约束的含义。
- ScrollGeometry 是上次完成布局的 ScrollView 局部 DIP 几何；它不触发布局，
  Measure 中不要拿旧结果反推本次自然尺寸。布局阶段读取实际 Viewport 和槽位，
  不从内部 ScrollBar 子树或内容宽度猜视口。
- 分开处理容器外留白、边框／圆角安全内缩、行内缩和内容到轨道的 Spacing，避免
  重复叠加。Spacing 垂直于滚动方向，不是轨道两端留白；隐藏内置条不等于禁用滚动。
  表格网格、紧包围轮廓与视口外框也不是同一个范围，短表收高须另查公开能力。
- 表格的 header、header-text、row 及网格／轮廓是 TableView 自有样式 Part，按该
  表格的样式名配置；不通过全局 Label 样式或给单元格加空列来模拟局部表头与轨道。
  树的行外观同样由 RowStyle 管理，行内 Label 样式不替代外层选中背景与焦点。
- SplitView 的 separator 常态线宽参与布局，HandleSize 是拖动／悬停范围，可以
  覆盖相邻区域。相邻滚动条等交互控件应避让热区；样式透明不使该区域失去命中。
- 通用 BindScroll 关联的是滚动轴，不提供两份异构文档间的语义位置映射。需要
  行／偏移几何时核对对应查询是否会滚动、展开折叠或取消 IME；不能把命令当只读查询。

## 菜单、弹层与编辑焦点

- 复用 MenuBar／MenuButtonGroup、Submenu 和 Command。Checked 由业务显式发布；
  激活不自动切换勾选，同一 Command 可供菜单和快捷键复用。布尔勾选不等于通用
  Radio／Mixed 命令组，互斥模式等规则由应用保持。
- MenuBarAuto 在 macOS 使用系统菜单时仍挂载，但不占窗口布局、不绘制；不要另外
  预留一个固定高度空行。原生窗口按钮由 HeaderBar／Chrome 协作，不靠普通按钮样式
  修改装饰色或猜测占位。MenuBarInWindow 表达业务菜单的呈现选择，不改变系统退出契约。
- MenuButton 的菜单是非模态自动关闭面，键盘由持焦点的锚点转发；PopoverMenu 默认
  模态，普通 Popover 的 Modal 与 AutoDismiss 独立。不能把所有菜单和浮窗视为同一种
  焦点策略，也不需要为每个控件自建原生弹层池。
- 逻辑焦点／CommitText 不表示原生 Popup 支持完整 IME。需要可输入候选列表时先核对
  原生能力；可以将真实 TextInput 保留在主窗口，使用普通 Overlay 呈现非模态候选，
  继续默认输入分发。关闭候选时保留有效定位，不把待卸载内容临时移到左上角。
- 菜单可能暂时取得焦点。编辑命令记住有效的编辑目标与业务身份，关闭后按明确策略
  恢复；捕获阶段不要拦截子 TextInput 的正常事件。PopoverMenu 先关闭菜单链再执行
  叶项动作，关闭回调中的常规模型清理由框架处理，不另加延时或手工重发来补旧版问题。

## 关闭、退出与持久化

- ui.Window 的 OnCloseRequest／gui.Window.ConnectCloseRequest 可以否决普通窗口关闭请求；
  Application.Quit 是终止请求，不等于逐窗发送关闭请求。Shutdown 是清理通知，
  不是取消或延迟退出的确认钩子，App.Post 在停止后可能被丢弃。
- 当前基线的 macOS 系统应用菜单、Cmd+Q／Dock 退出没有应用级可取消请求。
  未保存确认不能只接 Window.CloseRequest 就宣称覆盖全部退出路径。业务“退出”
  可以先完成确认／保存再调用 Quit；系统路径需要明确可接受的草稿／恢复策略及
  剩余风险，不能在 Shutdown 期间补弹确认框或偷偷拦截某一个快捷键冒充完整支持。
- NoKeepRunning 只决定窗口是否参与最后窗口自动退出的计数，不使其脱离应用清理。
  辅助窗口、编辑窗口和持久任务按实际职责选择，不因它是独立窗口就自动关闭保活。

## 核对能力边界，不复制旧补偿

当前基线的 Clipboard 只交换纯文本，不提供多格式及所有者代次。不能靠相同文本
猜测来自本应用并恢复私有富文本缓存，也不在文本中塞隐藏结构标记。Label 单行裁切
不是省略号；DropDown 不是可输入／筛选的 ComboBox。遇到这些需求先核对选中版本，
明确真实支持的替代方式，不虚构 API，也不把纯文本替代宣称为富文本往返已完成。

Clipboard.RequestText 回调可能同步发生。应用自行管理异步粘贴时，在发起请求前
建立目标／请求身份，回调时检查文档、选区及生命周期，避免写入已经切换的文档；
不要假定请求返回后才需要准备回调状态。
