# Platform 开发规范

本指南补充[仓库指南](../AGENTS.md)，适用于 `platform/` 全部代码。这里只维护长期规则，不记录功能进度或临时诊断。

## 阅读路由

- 涉及 Linux 原生调用：读 [Linux 规范](linux/AGENTS.md)。
- 涉及 Windows 原生调用：读 [Windows 规范](windows/AGENTS.md)。
- 涉及 macOS 原生调用：读 [macOS 规范](darwin/AGENTS.md)。
- `graphics`、`typography`、平台入口和测试中的平台专属代码，同样遵守对应平台规范，不因目录不同而免除。
- 结构地图见 [PlatformDev](../doc/PlatformDev.md)。公共 API 以源码及其注释为准；既有代码是写法参考，不是忽略原生契约或复制缺陷的理由。

## 绑定与适配边界

- 新增原生调用前，先搜索已有库、符号、类型及同类调用。扩展原包，不按 GOUI 功能重复建立绑定入口。
- 绑定按原生库、框架与类型组织，保留参数、返回值、错误和所有权语义；沿用所在包的函数、类型、常量和初始化风格，不为一次新增调用引入另一套绑定框架。
- 窗口模式、事件转换、能力判断、属性读取策略及 DIP 换算属于后端适配。绑定层不导入 GUI 策略，也不假设调用者一定是某种 GOUI 窗口。
- 原生请求被接受，不等于状态已经生效。查询须报告实际观察，不能把最近请求值当作系统事实。
- 不支持、暂不可用、用户取消和操作失败按接口契约区分，不以成功返回掩盖失败。

## FFI 与资源归属

- 每项新增资源明确所有者、借用/拥有关系、有效期、释放函数与线程。创建中途失败也要释放已取得的资源。
- 仅调用期间使用的 C 字符串采用 `cgo.CStringTemp`；需要独立长期存储时采用 `cgo.CString` 并由明确所有者调用 `cgo.Free`。如果原生 API 接管内存，必须使用其要求的分配/释放方式，不能混用 allocator。
- 原生 API 会复制输入还是保留指针，必须查契约。临时字符串、切片和结构体不能被原生异步保留；原生保存的回调及关联数据也要有完整生命周期。
- 指针转为 `uintptr` 后，检查调用桥是否保证存活、逃逸及地址稳定。必要时在绑定边界保活或固定内存；`runtime.KeepAlive` 不等于 pin，也不延长到函数返回后的异步使用期。不机械地给所有调用加 pin，更不能要求调用方碰巧拥有足够大的栈。
- ABI 核对整数宽度、符号、对齐、结构体布局、按值参数/返回及调用约定。涉及布局的新增绑定按风险补充 size/offset 等断言；编译通过不能替代原生调用验证。
- 原生对象遵循所属线程约束；回调跨线程时先投递事件循环。同步回调也可能重入并销毁对象，返回后必须重新检查生命周期。

## 改动范围与验证

- 公共契约改变时检查全部适用平台；局部整理不顺带重写其他已验证路径。发现历史偏离先记录、说明影响，再按获准范围处理。
- 不为减少代码或统一外观改变原生时序、资源隔离或失败语义；兼容分支需有原生限制证据及回归场景。
- 测试组织遵循 [Testing](../doc/Testing.md)，颜色、坐标、绘制与跨平台验收遵循根指南。不复制另一套测试分类或跳过规则。
- 交付前运行 `go test ./...`；按风险补充 ABI、逻辑、像素、跨平台编译与窗口验证。旧测试可能依赖桌面或产生文件，必须如实记录，不借规范整理迁移或删除。

## 修改前与交付前检查

1. 已有绑定在哪里？本次遵循哪个具体类型或函数的写法？
2. 标识、对象、内存和回调由谁持有，何时及在哪个线程释放？
3. 返回的是系统观察、能力判断，还是仅提交请求？
4. 是否改变线程、事件时序、坐标单位、所有权或失败语义？
5. 哪些测试通过、失败、跳过、未执行？哪些只有编译结果，哪些有桌面验收？
